# S31-B — LF Work Package v0.2 Candidate Design

Status: CANDIDATE DESIGN / NOT PROMOTED
Work Package: `WP-S31-B-001`
Base main: `ee7aca94c672fcc555db90962f09fe439eedf4f0`

## Objective

Evolve the bootstrap Work Package using only source-grounded fields from the existing Task Packet, S30 pre-execution assurance, and observations generated by real S31 execution.

## Preserve from existing Task Packet

Keep as transversal semantics:
- identity / execution / step;
- worker;
- objective and input refs;
- allowed tools;
- read/write scopes;
- forbidden actions;
- required output;
- acceptance/failure/blocking assertions;
- retry policy;
- judge;
- next step;
- source snapshot;
- attempt.

Do not preserve skill-specific constants as LF-wide constants. `operation_code=BUILD_INTEGRAL_STORY_CREATOR_LF`, fixed worker naming and fixed retry=2 become extension/policy bindings, not core Work Package identity.

## Preserve/generalize from S30

Promote the semantics, not S30 ownership:
- resolve-before-build sequence;
- cheap preflight before expensive/material work;
- one causal chain / one active writer;
- structured blocker + invalidation condition;
- current frontier + safe parallel work;
- evidence for every PASS;
- exact source/currentness binding;
- fail closed on unresolved critical dependency;
- closure recomputed from evidence ledger.

## Candidate v0.2 additions generated by S31 execution

### WP-EVO-001 — frozen source binding

For each material source require one of:
- exact Git/blob/commit revision;
- SHA256 digest over canonical source payload;
- governed live-current authority receipt.

A path alone is insufficient.

### WP-EVO-002 — executed validation receipt

Add `executed_validation[]` with at least:
- validation id;
- exact command/runner;
- execution ref kind;
- base SHA;
- branch-head SHA;
- executed SHA;
- exit/result;
- output/evidence ref.

Validator presence is structural evidence only.

### WP-EVO-003 — ref-kind-aware currentness

Currentness receipt distinguishes:
- `BRANCH_HEAD`;
- `PR_MERGE_REF`;
- `COMMIT_EXACT`;
- `LIVE_AUTHORITY`.

`EXACT_HEAD` is valid only when executed SHA equals branch-head SHA.

### WP-EVO-004 — fresh EKB binding

Add execution-bound EKB applicability:
- preflight run id;
- source revision/readback identity;
- matched codes;
- severity;
- applicable/not-applicable decision;
- gate/control mapping;
- unresolved High/Critical => fail closed.

### WP-EVO-005 — macrolot continuation

A causal blocker does not end a run by itself. Frontier recomputation is mandatory. Safe parallel work continues until exhausted or invalidated.

## Compatibility rule
