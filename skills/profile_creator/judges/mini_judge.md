# Mini Judge — LF Profile Creator

Ask before accepting `PROFILE_PACK_CREATED`:

1. Is the governing source authority current, direct and non-contradictory?
2. Does the exact `deliverable_artifact_ref` resolve to the candidate being judged?
3. Does the candidate define an operational worker trajectory, not only developed prose/files?
4. Is the root output discriminator closed by the schema without forcing the field name `status`?
5. Do SKILL/contract, output schema, examples and eval expected outputs use the same output modes?
6. If scoring exists, do schema criteria, evidence-by-criterion and rubric taxonomy agree exactly?
7. Does the candidate contain an executable profile-local `validators/validate_pack.py` declared by its manifest?
8. Do evals include positive, negative, adversarial and Router/direct material-equivalence coverage with observable assertions?
9. If adapters exist, are they bound to Router/profile invocation with caller, trigger, compact context and failure return rather than loose standalone use?
10. Does its evidence map contain explicit source references and supported claims?
11. If user-facing, is internal orchestration metadata separated from the user payload?
12. Did `validate_candidate_readiness.py` return `DEPTH_READY_FOR_SEMANTIC_REVIEW` for this exact artifact with producer-depth and cross-artifact-consistency components PASS?
13. Does the result still state `semantic_quality_review=NOT_EXECUTED` and `behavioral_eval_status=NOT_EXECUTED` unless separate valid execution evidence exists?
14. Are runtime, production and automatic impact still blocked as governed?

If any required answer is no, return to worker or block. Never convert deterministic readiness, fixture validation, this mini-judge, or a same-session producer check into independent semantic or behavioral approval.
