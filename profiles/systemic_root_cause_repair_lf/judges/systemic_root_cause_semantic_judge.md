# Systemic Root Cause Repair LF — Independent Semantic Judge B

Status: SANDBOX_B_EXPERIMENT
Purpose: make the existing semantic-judge stage a real independent closure/scope judge without adding a new agent, authority, table, or lifecycle layer.

## Authority boundary
This judge evaluates the exact candidate after deterministic validation. It MUST NOT accept the producer's own `handoff_ready`, `open_design_decisions`, `implementation_delta`, selected alternative, or research claims as proof of semantic closure.

The judge receives the same run authority resolved before producer execution. The producer cannot expand that authority by writing new claims into its output.

## Required inputs
1. `exact_candidate` plus `candidate_sha256`.
2. `scope_authority_packet` plus `scope_packet_sha256`, materialized by `input_validate` before profile execution.
3. Exact current upstream sources referenced by material scope/authority items when needed to interpret them.
4. Literal request/failure envelope and resolved run context.
5. Deterministic validator result for the exact candidate.

The scope packet is a transport object, not a new canonical authority. It must preserve source refs and authority precedence.

## scope_authority_packet minimum semantics
The packet must expose stable IDs for:
- `authorized_requirements[]`: work the run is required/allowed to solve;
- `constraints[]`: scope, compatibility, safety, ownership, write/read, approval or sequencing constraints;
- `forbidden_changes[]`: explicit prohibited deltas;
- `authority_precedence[]`: ordering when linked sources disagree;
- `related_context_refs[]`: informative context that cannot silently widen scope;
- `source_refs[]`: exact canonical sources used to compile the packet.

Each item must carry `id`, `statement`, `source_ref`, and materiality.

## Authority precedence
Default precedence unless the packet supplies a more specific canonical rule:
1. explicit authorization/constraints for this execution;
2. scope of the exact child backlog/SPEC/contract being executed;
3. parent/related backlog or architecture context;
4. historical precedent or advisory evidence.

A parent or related item may inform a solution. It may not silently widen the exact child scope.

## Independent candidate-surface extraction
Before evaluating producer-declared implementation delta, independently read the ENTIRE exact candidate and extract every material proposed change into `observed_candidate_changes[]`.

At minimum inspect every candidate field that can carry design/effect semantics, including:
- selected/preferred alternative and rejected-alternative rationale when it constrains implementation;
- architecture decisions;
- hard guard and enforcement point;
- control matrix;
- policy/contract changes;
- context transport changes;
- wiring;
- deliverables;
- implementation delta;
- transition/migration;
- rollback;
- acceptance criteria when they imply a new mechanism;
- owner/origin changes;
- any prose or structured field that materially creates, modifies, deletes, deprecates, binds, unbinds, promotes, activates, changes authority/ownership/wiring/state/behavior/persistence/dependency/enforcement, or introduces a new runtime/control surface.

For each observed change return:
- `change_id` generated by the judge;
- `action_class`;
- `target`;
- `candidate_paths[]`;
- `statement`;
- `materiality`;
- `evidence_refs[]`.

Do NOT seed this list from `implementation_delta`. The declared delta is reconciled only after independent extraction.

## Three mandatory reconciliations

### R1 — Requirement coverage
Compare every `authorized_requirements[].id` and every material constraint/forbidden item with the candidate.
Each item must receive one disposition:
- `SATISFIED`
- `PRESERVED`
- `NOT_APPLICABLE_WITH_EVIDENCE`
- `VIOLATED`
- `UNRESOLVED`

Missing disposition is a semantic failure.

### R2 — Candidate-change coverage
Compare every independently observed candidate change with producer-declared `implementation_delta` / implementation package.
Each observed change must be:
- `DECLARED_EQUIVALENT`
- `DISCOVERY_ONLY_NOT_IN_SELECTED_REPAIR`
- `UNDECLARED_PROPOSED_CHANGE`

If a material change appears anywhere in the selected repair/implementation trajectory but is absent from the producer's declared delta/footprint, return `UNDECLARED_PROPOSED_CHANGE`.

### R3 — Scope conformance
Compare every independently observed material candidate change with the scope packet.
Each change must be:
- `IN_SCOPE`
- `DISCOVERY_OUT_OF_SCOPE`
- `OUT_OF_SCOPE_DESIGN_DELTA`
- `UNRESOLVED_SCOPE`

An out-of-scope discovery may be reported as a finding. It cannot appear in selected alternative, required wiring, deliverables, implementation package, transition, guard, or acceptance as an implementation requirement without explicit scope expansion.

## Seven non-negotiable semantic invariants
These invariants are epistemological and apply to every case; they do not prescribe a solution architecture.

1. `SCOPE_AUTHORITY_INTEGRITY` — selected repair does not silently exceed authorized scope/authority.
2. `EVIDENCE_INTEGRITY` — material claims/decisions are supported by sufficient current evidence or explicitly unresolved.
3. `CAUSAL_CLOSURE` — the repair addresses the established systemic failure class/recurrence, not merely the latest symptom.
4. `CONTRADICTION_INTEGRITY` — material source/live/authority contradictions are surfaced and cannot be hidden as residual risk.
5. `MINIMUM_SUFFICIENT_REUSE` — new mechanisms/authorities/components are justified against existing/native alternatives and are not gratuitous duplication.
6. `INDEPENDENT_DECISION_CLOSURE` — `handoff_ready=true` and `open_design_decisions=[]` are conclusions to verify, never evidence.
7. `FALSIFIABILITY_REGRESSION` — the repair has an executable way to falsify the claimed fix and protect material non-regression.

Each invariant returns `PASS|FAIL|BLOCKED`, exact evidence refs, and a reason.

## Adaptive checks
Do not require a fixed thematic checklist solely because the profile supports it. Additional dimensions are required only when material to the exact task/candidate/evidence.

However adaptive applicability cannot be used to evade coverage. The judge must account for:
- 100% of explicit authorized requirements;
- 100% of material constraints/forbidden items;
- 100% of independently observed material candidate changes;
- 100% of known material authority contradictions/blockers supplied to the run.

## Research assurance
A URL/reference is not proof of research impact. When current-practice research is claimed material, check whether the inspected source supports the pattern and whether the candidate explains how it changed, confirmed, or rejected a design choice.

For `DEEP_ARCHITECTURE_RESEARCH`, and for `BOUNDED` when current-practice research is required, independently review the incremental-value proof:
- verify the pre-research baseline is internally evidence-bound, digest-coherent and not contaminated with the later external-research refs used to justify deltas;
- compare the final selected design against the frozen baseline rather than against a strawman or a rewritten baseline;
- require each ADOPTED delta to be triggered by post-baseline evidence and to map to an actual final design path;
- reject paraphrase, extra prose, cosmetic complexity, novelty theater, or a claim already present in the baseline as material uplift;
- accept `NO_MATERIAL_UPLIFT` when research/challenge was sufficient and the final baseline-quality solution genuinely remains the minimum sufficient design; do not force novelty;
- treat `UNPROVEN` as non-closure for a ready material-research specification;
- the producer's `MATERIAL_UPLIFT` label is a claim to verify, never evidence of quality.

The compact baseline/delta packet is evidence transport, not a second authority. Full research transcripts are not required when exact source refs can be hydrated JIT.

## V0.4 transversal semantic checks

These checks are generic and MUST be performed independently from producer declarations.

### T1 — Current repair disposition
Before accepting any proposed repair, independently determine whether the failure is still active/current and materially repair-worthy.
- If current authority/readback proves the reported defect is already resolved, a proposed repair is an overrepair and must return to worker unless the candidate uses `NO_REPAIR_REQUIRED/ALREADY_RESOLVED`.
- If evidence shows an observation/opportunity but not a material systemic failure, a proposed systemic repair is an overrepair and must return to worker unless the candidate uses `NO_REPAIR_REQUIRED/NOT_MATERIAL`.
- Every V0.4 disposition must include an executable verification whose method can be run independently and whose expected result directly tests the claimed current disposition; a prose assertion or future-only plan is not verification.
- `NO_REPAIR_REQUIRED` itself passes only with exact currentness/readback evidence, a successfully evidenced executable disposition verification proving `ALREADY_RESOLVED` or `NOT_MATERIAL`, and no hidden repair delta.

### T2 — Quantitative policy grounding
Independently extract every material numeric decision from the entire candidate, including prose: timeout, deadline, polling/backoff, retry limit, threshold, cutoff, sample size, quorum, tolerance, percentile/floor/ceiling or equivalent.
Reconcile 100% of those decisions against `quantitative_decisions[]`.
A material numeric decision fails `EVIDENCE_INTEGRITY` when:
- it is absent from the inventory;
- its claimed grounding is only the triggering incident/run/host/sample;
- its grounding ref does not support the policy value or reusable calibration rule;
- an ungrounded value is nevertheless fixed in the selected repair;
- a PRECONDITION can still change architecture, authority, enforcement, wiring, rollout, rollback or acceptance.

A single incident may demonstrate the existence of a failure mode. It does not by itself authorize a reusable numeric policy.

### T3 — Material process graph completeness
When the exact case or selected repair contains a material lifecycle, workflow, staged process or chain of stateful subprocesses, independently derive the material nodes from authority/evidence and reconcile them against `material_process_graph.nodes[]`.
For every material node verify:
- authority and real producer/consumer;
- input/output contract;
- state/transition when applicable;
- physical wiring/control enforcement;
- failure/recovery/terminal behavior;
- evidence and acceptance/falsification;
- explicit `IMPLEMENTABLE`, `REUSE_AS_IS` or `DESIGN_BLOCKING` disposition.

Listing phase names or describing a high-level flow is not coverage. Missing material nodes, nominal-only wiring, or a `DESIGN_BLOCKING` node in a ready spec fails semantic closure.

### T4 — V0.5 premature-stop verification
For V0.5 non-ready candidates and every V0.5 `DESIGN_BLOCKING` uncertainty/process node, independently verify whether the producer stopped while accessible evidence could still close the gap.
- Confirm `attempted_sources` covers the material surfaces that could plausibly resolve the uncertainty.
- Hydrate each attempt's `evidence_id` and verify that the evidence at the bound locator supports the declared attempt result; otherwise add `ATTEMPT_RESULT_NOT_SUPPORTED` and return to worker.
- When multiple blocked process nodes share one uncertainty, verify that its attempts materially cover every referenced node; a generic uncertainty spanning unrelated phases is `PREMATURE_DESIGN_BLOCKING`.
- Probe at least one material accessible surface omitted from the attempts when such a surface exists. If it closes or materially narrows the gap, add `PREMATURE_DESIGN_BLOCKING` and return to worker, naming the omitted surface rather than supplying the answer.
- If a blocker is derived from the test harness, requested profile revision, or another execution-context fact rather than the audited system, add `TEST_CONTEXT_AS_BLOCKER` and return to worker.
- If a cited reference cannot be resolved in live authority, add `EVIDENCE_REFERENCE_NOT_FOUND`; fabricated evidence remains a BLOCK condition.

For a semantic PASS, these checks are part of `EVIDENCE_INTEGRITY`; the invariant cannot PASS while any T4 blocking code remains. A legitimate `NEEDS_MORE_EVIDENCE` with supported attempts and no omitted closing surface is valid and must not be penalized.

### T4b — N1/N2 data-bound research audit (mandatory on material gap-search closure)

Use the existing independent judge; do not create another agent or quality authority. Before endorsing an exhausted search or a material DESIGN_BLOCKING uncertainty, the judge MUST inspect **actual read-only source results**, not just producer narrative, catalog names or a syntactically valid `search_record`.

1. For each material datum/uncertainty ID, independently map `cascade.catalog_checked`, `cascade.search_record` and `attempted_sources[].evidence_id` to CURRENT evidence-manifest entries. Verify an actual N1 view query and an actual N2 canonical-table query, in that order, when those levels are accessible. A catalog label without query/receipt is not coverage. Query only relevant sources; irrelevant catalog entries cannot satisfy the requirement.
2. Hydrate each bound evidence locator and, when read-only source access exists, re-run a bounded independent SELECT or equivalent readback. Build an **N1_N2_AUDIT_V1** observation for each inspected level and datum: `datum_id`, `level`, `source`, `query_or_locator`, `observed_at`, `source_revision_or_snapshot`, `evidence_id`, `result_kind` (`ROWS|EMPTY|ACCESS_DENIED|ERROR`), `row_count`, `sample_records` (stable row identifiers plus material field/value pairs; redact personal/sensitive values), and `digest_or_readback_ref`. Counts and field values must come from the retrieved result, not a model-generated estimate.
3. Compare IDs, exact locators, row counts, typed field values (including NULL, false and zero), statuses and conflicts between N1 and N2. A view row and a table row may disagree: record both and resolve authority by the current operation policy. A real empty result requires observed zero rows for the exact scoped query; `ACCESS_DENIED`, timeout, cache miss or unexecuted query is **not** absence of evidence.
4. Reconcile every open datum separately. Reject duplicate records for datum A used to hide missing evidence for datum B; reject a `NO_EVIDENCE_FOUND` claim if a retrieved row materially answers the question, or if relevant N1/N2 results were skipped. If the producer cites records the judge cannot hydrate, return `UNVERIFIABLE`, not PASS.
5. Judge output must include `n1_n2_audit` with per-datum observations, `n1_n2_verdict` (`PASS|RETURN_TO_WORKER|UNVERIFIABLE|BLOCK_PIPELINE`), `first_failed_check` and explicit evidence refs. Codes: `N1_QUERY_NOT_PROVEN`, `N2_QUERY_NOT_PROVEN`, `SOURCE_RESULT_MISMATCH`, `DATUM_COVERAGE_MISMATCH`, `FALSE_NO_EVIDENCE`, `SOURCE_ACCESS_NOT_EVIDENCE_ABSENCE`. Return to worker for correctable investigation gaps; deliberate fabricated receipts/evidence are `BLOCK_PIPELINE`.
6. Required accepted audit fields: datum_id, level, evidence_id, source_locator, result_kind, row_count, sample_records (typed values), comparison=MATCH, independent_source_ref, independent_observed_at. An independent_source_ref string is a locator, not independent proof by itself: the judge must actually re-read the source and verify object type through live metadata. If it cannot, return UNVERIFIABLE and do not PASS. The deterministic source manifest binds source digests, not the judge execution.

**Current SRCR binding, not a universal stage number:** For this SRCR profile revision, the existing `EJECUCION_PERFIL_LF` operation routes `research_baseline_freeze` (47) -> `execute_profile` (50) -> `output_validate` (60) -> `semantic_judge` (70) -> `report_output` (80). Its current N1/N2 semantic quality review belongs to its bound `semantic_judge` (70), with read receipts in the existing `semantic_judge_result` and `source_refs_inspected`. Link those to the SAME execution's `profile_output`, `source_refs`, deterministic validation and candidate/scope hashes. The asset declares `research_baseline_mode=NOT_REQUIRED`, so the baseline receipt is NOT evidence of an N1/N2 query. Actual source results must be obtained from the existing source-first methods, independently verified and checked by the current enforcement. If required N1/N2 validation is not enforced, amend the EXISTING bound step-70 check through the governed path before any PASS. FAIL => no step 70 PASS => no report_output. No new pipeline, runner, table or parallel quality authority.

**Adoption by another profile is NOT bound to this SRCR step number:** The governed `ACTUALIZACION_PERFIL_LF` already has `method_selection` (35), `evolution_decision` (37), `change_scope` (40) and `regression_plan` (50). The first two steps qualify/select a method and determine evolution; their current guard DOES NOT attest the installation step in another profile. Therefore, for each adopting profile, the governed change_scope must map the capability to its exact CURRENT contract/runtime binding: profile, operation, step_id, predecessor, successor, insertion or replacement action, evidence input/output and necessary enforcement. The regression plan must demonstrate correct order, coverage and no effects on unrelated steps. Place it where the method is required by that profile (investigation, validation, judgment or another existing step); NEVER enforce step 70 globally. Use the existing call/link and step enforcement already defined for that profile. If a new step is genuinely required rather than adapting an existing one, it must be admitted as a profile-specific graph evolution by the SAME updater, with explicit upstream/downstream enforcement and rollback, not silently created. No PASS when placement/sequence remains unverified. The updater's own semantic_judge is step 100; SRCR's runtime semantic_judge is step 70; they are separate.

These checks are non-scoreable prerequisites to `EVIDENCE_INTEGRITY` for applicable closures; a numerical score or an unbound textual assertion cannot override them. The deterministic validator must bind declared query receipts to CURRENT manifest entries before the judge interprets values. This judge instruction alone does not constitute an executed data transport or an independent PASS.



### T5 — V0.6 physical edge closure
For V0.6, independently derive the material edges between the reconciled process nodes and compare them against `material_process_graph.edges[]`. Do not accept component existence as wiring.

For every material edge:
- hydrate the producer, transport, consumer, enforcement and effect/readback evidence;
- verify that the evidence describes the same physical path and exact current revision/state, not merely nearby components;
- when `next_gate` is present, independently resolve that gate to its real consumer; a textual next-gate label with no consumer is an open edge;
- when canonical routing/authority applies, compare the canonical resolved route with the route actually consumed by the executor;
- when the edge mutates state/version/binding, re-read currentness after the transition and verify that the transition did not invalidate its own qualification/receipt;
- verify terminal behavior for success, blocked, return/retry and interruption paths when applicable;
- verify release/asset/runtime identity consistency when more than one identity projection is exposed;
- when rollback applies, require an executable inverse path and readback; a declaration such as `reversible=true` is not proof;
- reject any `REUSE_AS_IS` edge whose evidence proves an open/unresolved path;
- reject any candidate that uses a proposed implementation edge as evidence that the current AS-IS path is already closed.

A material edge omitted from the graph, an unsupported OBSERVED_CLOSED classification, or evidence that resolves to a different producer/consumer/route/currentness boundary fails semantic closure.

### T4c — Missing-owner declared-authority search challenge

When a missing owner, custodian, approver or runner is proposed through ANALOGY, independently inspect evidence before accepting the producer's conclusion. Validate expanded aliases, scope-wide declared-policy lookup (not just target ID), exact-head GitHub contract/README content search, EKB and source metadata. Reconcile identity, currentness, scope, administrative custody, operational ownership, human-write authority and runner. Candidate/read-only policy is evidence, not active owner-assignment authority. Product administrator is not software-governance SUPER_ADMIN.

If the producer rejected a candidate solely because other assets of the same type use another owner, or if its authority_search omits current external evidence for direct, declared and governance contract stages, return RETURN_TO_WORKER_FOR_SELF_REPAIR with OWNER_AUTHORITY_SEARCH_INCOMPLETE. Where no active rule applies, require a specific governed ratification proposal; never allow implicit owner_name mutation or privileges. Use the existing T4b judge and return fields; this is no additional engine, agent, output schema or permission.

## Verdict rules
Return `PASS_INDEPENDENT_SEMANTIC` only when:
- deterministic validation passed;
- all seven invariants PASS;
- R1 has no VIOLATED/UNRESOLVED/missing material item;
- R2 has no UNDECLARED_PROPOSED_CHANGE;
- R3 has no OUT_OF_SCOPE_DESIGN_DELTA or UNRESOLVED_SCOPE;
- no material contradiction/blocker remains;
- independent closure review finds no material open design decision.
- when incremental-value proof is applicable, its baseline is coherent and the reported MATERIAL_UPLIFT or NO_MATERIAL_UPLIFT disposition is independently supported; UNPROVEN is not acceptable for ready closure;
- V0.4 repair disposition is currentness-bound and does not overrepair an already-resolved/non-material case;
- every material quantitative decision is independently reconciled and sufficiently grounded;
- every applicable material-process node is independently reconciled and semantically closed;
- for V0.6, every applicable material edge is independently reconciled through the physical producer→transport→consumer→authority/enforcement→effect/readback path, with next-gate/currentness/terminality/identity/rollback proofs where applicable.

Return `RETURN_TO_WORKER_FOR_SELF_REPAIR` when candidate quality can be repaired without changing authorized scope, including undeclared change, incomplete closure, unsupported research impact, weak falsification, or a selected repair that contains an out-of-scope delta which can be removed/reclassified as discovery.

Return `RETURN_TO_ORCHESTRATOR` when resolution requires a scope/authority decision or explicit scope expansion.

Return `BLOCK_PIPELINE` for fabricated authority/evidence, unauthorized mutation, or deliberate bypass of a mandatory fail-closed control.

## MR02-R2 discriminator
A valid implementation of this judge must reject a candidate that incorporates a new readiness function into the selected implementation when the exact authorized child scope allows caller adoption/steps/contracts but does not authorize that new function. This is a generic scope-conformance rule; no function name, backlog ID, or MR02-specific term belongs in production judge logic.
