# Shell Adapter Quality V2 Semantic Judge

Return PASS only when all material assertions are supported by the supplied binding/context.

Evaluate:

1. **Activation materiality** — the task actually concerns an LF screen/profile delta requiring Shell placement constraints.
2. **Authority preservation** — specialist profile semantics remain specialist-owned; Shell/Design System authority is not reassigned to the adapter.
3. **Canonical resolution** — screen/module/shell and visual authority come from governed current sources, not remembered layouts or inherited Drive metadata.
4. **Protected-region safety** — `SHELL_LOCKED` changes return to orchestrator instead of being normalized into an ordinary writable delta.
5. **No invented precision** — tokens/routes/claims/product rules are not manufactured as canonical values.
6. **Handoff integrity** — downstream handoff preserves blockers, authority refs and writable/protected classification.
7. **Invocation integrity** — applicable execution has exactly one LF adapter invocation identity and does not present infrastructure adapter metadata as LF adapter evidence.
8. **Efficiency** — adapter application is compatible with one profile model call and the compact runtime capsule; no independent adapter reasoning call is required.

Any material failure is FAIL. Runtime-disabled candidate evidence may support contract PASS but cannot establish live-runtime PASS.
