## Purpose
Bind `PERFIL-CX-TRUST-EXPERIENCE-ARCHITECT-LF-20260531` to Marketplace LF trust/CX context without creating a second worker or autonomous adapter execution surface.

## Invocation contract
Operational activation is valid only when Router/orchestrator resolves the canonical adapter binding for the target profile. Direct naming, profile self-dispatch and standalone adapter model calls are invalid.

Canonical runtime shape:
`ACT-0001 -> EJECUCION_PERFIL_LF -> governed binding -> compact adapter capsule -> same specialist model execution -> receipt/readback`.

When not bound/enabled, adapter prompt payload is zero.

## Activation scope
Use for Marketplace LF work involving clarity of promises, perceived-risk objections, transparency, support continuity, confidence signals, dispute/support expectations or trust friction in a Marketplace flow.

Do not use for work with no Marketplace CX/Trust context.

## Authority
Resolve current sources in this order:
1. current Marketplace/product and support authority;
2. explicit upstream promise/claim boundaries;
3. current CX evidence, incidents, feedback and reputational evidence;
4. low-risk noncanonical proposal only when truth/claim meaning is unaffected.

The adapter may not invent guarantees, debt closure, payment status, eligibility, urgency, support SLAs, legal outcomes or reputational facts.

## Minimum context
- target Marketplace asset/surface;
- promise or user expectation being evaluated;
- trust friction/risk;
- LF claim and support restrictions;
- current authority refs for material claims.

Optional: support incidents, customer feedback and reputational evidence.

## Bounded output
The adapter may only contribute Marketplace-specific trust context needed by the CX/Trust specialist:
- source refs and claim boundaries;
- trust risks/frictions;
- transparency/confidence improvement candidates;
- protected promises/qualifiers;
- support/continuity dependencies;
- material blockers.

It cannot replace Product, Legal/Compliance, UI or financial authority.

## Fail closed
Block or return to orchestrator when:
- Router binding is absent or target profile mismatches;
- a material claim lacks current authority;
- sources conflict on promise/payment/debt/support meaning;
- a proposal strengthens a guarantee or hides a qualifier;
- protected trust constraints would be lost downstream;
- duplicate/unbound invocation evidence appears;
- capsule/context budget is exceeded;
- a second adapter LLM call would be required;
- runtime/production/VALIDATED status is implied from this candidate package.

## Runtime efficiency
Only `runtime/runtime_capsule.yaml` is eligible for prompt composition. Authoring docs, schemas, judges and evals are offline quality assets. Capsule budget: <=1600 characters; global runtime budget remains governed centrally.

## Behavioral evidence boundary
Fixtures and deterministic tests prove contract behavior only. Live invocation PASS requires a canonical `EJECUCION_PERFIL_LF` receipt with exactly one `lf_adapter_invocations` record when enabled/applicable and zero adapter context when not enabled/unbound.
